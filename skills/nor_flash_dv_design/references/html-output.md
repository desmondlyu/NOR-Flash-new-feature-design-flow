# HTML 輸出規範

## 使用範本

讀取並複製 `../assets/verification-plan-template.html`，保留深色視覺風格與互動骨架，填入**已完成 `speak-human-tw` 與 `asd-ste100` 第二輪改寫**的定稿內容。範本是不帶特定料號規格的空版型，所有 `{{...}}` 佔位符都必須替換乾淨。它借用 `NOR_Flash_DV_Guide_V6.html` 的閱讀架構，不包含該案例的實測資料。

每個功能放在一個 `article.chapter`，配上唯一 `id`。新增章節時，上方導覽列會由 JavaScript 讀取 `data-title` 自動產生。章節內的圖形、測項表列與錨點都要同步加上該章唯一前綴，避免重複 `id`。只有單一功能時，底部的上一章／下一章按鈕會自動隱藏。

## 內容與圖形

- 每章照「概念 → 執行前說明 → 產品規則與狀態圖 → 共通方法 → 已選測項與流程 → 復原與判讀 → 待確認與來源」排列。邊界與未定義用法只展開已選項目，沒有已選項目時簡述即可，並刪掉範本裡的 Flow X 卡片與連結，不要為了填滿範本反過來硬湊測項。
- 首頁標明本次用途與機台範圍。每個已選測項表前寫清楚情境依據、要抓的錯與不可取代性。多個測項共用同一個 Flow 時一樣逐項交代，用短句或清單寫，不要把表格加到十幾欄。
- 共通方法的測試區域表須列出本次選用之頭、中、尾基準區、鄰區與例外區的確切十六進位範圍、區域配置單位大小、基準角色與算式／規格依據。必要時標明 Die ID、選擇器設定、完整邏輯位址與實際傳輸位址，顯示位數依主 skill 與本次指令格式決定（3-Byte 傳輸欄位用 6 位十六進位，4-Byte 傳輸欄位用 8 位十六進位，禁止為了塞進版面而截斷高位元），並分開交代操作影響範圍與讀回觀察範圍。圖、表與復原段落必須共用同一份位址配置，不得拿公式取代實際十六進位位址，也不得把三區取樣寫成已涵蓋全晶片。
- 補充候選獨立成一張短表，只列情境、新增價值與納入條件，不展開逐步流程也不放 Flow 連結，沒有候選時整張表拿掉。合併或不採用的情境只摘要關鍵取捨。
- 需要 CP 建議時獨立一節，列出攔截目的、判定依據與證據狀態。缺實測／失效案例支持的項目一律標「CP 候選／攔截假設待驗證」，不包裝成正式量產流程。不必硬讓每個 DV 測項都對到 CP，沒需求時直接移除 CP 區塊。
- 真實上下電只列機台允許時的補充建議。高頻與外部 `/RESET`、`/HOLD`、`/WP` 腳位控制不進預設流程。不加測試時間預算或成本欄位。
- 主測項表維持「步驟／做什麼／預期」三欄（Flow X 可加「要問 Designer」），保持好讀。
- 每個納入執行計畫的 Flow 標題要講明目的，必要時補一段「為什麼這樣測」，並在標題與測項表之間放至少一張專屬內嵌 SVG。圖面採「方塊清楚、字少好懂」原則：畫出起始資料與確切位址、關鍵條件、操作、判斷、應變／不變區域及失敗停止／復原方向，詳細步驟留給表格承接，太擠就拆圖，不硬塞進固定高度。
- 產品狀態行為圖必須獨立畫出「初始狀態 → 指令與條件 → 操作後狀態或維持不變」，只要功能有狀態變化就不能省。沒有狀態切換時改畫資料前後對照圖並說明原因，未知分支標「待確認」。
- 在相關 Flow 的說明區列出關鍵異常路徑（初始狀態、操作順序、可能異常、違反規則、對應測項連結與防誤判做法），並標明是文件推演還是實測結果。
- 每章具體寫出採用的假設、未涵蓋狀態／條件與影響，不要只寫一句籠統的「未窮舉」。
- 參考依據附上方法來源 [pstack /statechart](https://github.com/cursor/plugins/tree/main/pstack/skills/statechart)（與產品規格來源分開列，引用方法不代表跑過形式驗證工具），並附上「文字編輯參考」記錄本次實際讀取與套用的 `speak-human-tw` 與 `asd-ste100` 版本或讀取日期。
- 總覽用 HTML 卡片加箭頭，流程與狀態用內嵌 SVG，兩者都不依賴 Mermaid。正驗與反驗可放在同一個功能 Flow，不必硬拆成四章。
- 未定義項目寫明「可能結果／觀察點／要問 Designer」，不拿舊樣品的反應當成新料號規格。還沒實測時標「待審查／未執行」，頁面不放假造的通過率或 PASS 統計。
- **文字與結構硬指標（`speak-human-tw` + `asd-ste100`）**：
  - 全文、圖說與表格內**嚴禁出現全形分號**（STE Rule 8.1），一律拆成句號短句或 `<ul><li>` 清單。
  - 超過 3 條規則或跨測項共通條件，改用 `<ul><li>` 清單，禁止用 `<br>` 塞在同一大段。
  - 同一個工程名稱與確切位址全篇寫法一致，不用單字母目標代號頂替完整敘述，Flow 與步驟編號只作定位。
  - 測項表的「做什麼」欄位用完整主動祈使句（每句都有明確動詞），前置與禁止條件寫在動作前面。
  - 統一台灣工程用語（如 `address` 一律寫「位址」，禁止寫「地址」），刪掉「此文件製作過程未操作晶片」等對 Prompt 交差的免責套話，也禁止在每個測項開頭重複蓋章「AI 推演，依 R…」。

## 技術要求

- 單檔 HTML，`UTF-8`、`lang="zh-Hant"`、`viewport`，CSS、JavaScript 與 SVG 全部內嵌，零外部字型、零 CDN、零網路請求、免建置即可直接點開。
- 章節切換、上一章／下一章與測項錨點連結都能正常運作，關掉 JavaScript 時仍顯示全部章節且錨點可跳轉。
- SVG 加上 `<title>`，按鈕與連結支援鍵盤操作與清楚焦點框，不單靠顏色區分結果。
- 窄螢幕下讓圖與表格在各自容器內橫向捲動，不撐破整頁寬度。
- 列印時自動展開全部章節與 `<details>` 參考依據、隱藏導覽列與按鈕，改用白底黑字並避免表格列被切半。
- 外部文件文字與來源做好 HTML 跳脫處理，不用 `innerHTML` 塞入未驗證字串。

## 完整敘述與圖表導覽

照主 skill「測項敘述與流程示意圖」寫出完整位址、範圍、資料與條件，正文與 SVG 圖內都用完整中文意義取代時序符號（原始符號只留給可展開來源對照），未知位址或超時上限列待確認，絕不瞎填。

每個計畫內 Flow 都要有自己的專屬 SVG 圖（含未執行的預檢、功能、已選探索與復原），不能拿產品狀態圖頂替。補充候選不畫 Flow 圖。

總覽卡片連到 Flow，SVG 裡的操作方塊連到測項表列，表列連回原圖，連結文字寫清楚目的地名稱與位址，跨章跳轉先顯示目標章節再捲動。所有看得見與輔助閱讀的文字（含 SVG `text`／`title`／`desc`、`aria-label`、`alt`、`data-title`）都必須通過雙技能改寫與保真回讀，排版後改動過的字也要重檢。任一必讀文字參考檔拿不到時，停在文字草稿，不發正式 HTML。

## 交付檢查

1. **檢查測試設計與位址基準**：核對產品狀態、關鍵異常路徑、情境依據、不可取代性、假設與未涵蓋範圍。核對頭、中、尾基準區與有效視窗交集換算正確、單位對齊、目標與鄰區無未揭露重疊、無未說明依據的隨機位址，並確認跨章、SVG、測項表與復原位址完全一致。確認補充候選沒展開流程、CP 證據沒誇大、機台限制前後一致、無殘留佔位符或舊案例數值。
2. **檢查文字品質**：確認 HTML 內全形分號數量為 `0`、無「地址／位址」混用、無目標代號輪替、步驟都有動詞且條件在前、無 AI 交差免責套話與重複蓋章。改寫對照摘要只列真實修改，最多 5 處，不足不湊數。
3. **實開瀏覽器檢查**：實際檢查桌面與窄螢幕、章節切換、直接錨點跳轉、往返連結、關 JavaScript 閱讀與列印預覽。沒開瀏覽器就不能寫成已做視覺檢查。
