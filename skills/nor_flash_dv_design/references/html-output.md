# HTML 輸出規範

## 使用範本

讀取並複製 `../assets/verification-plan-template.html`，保留視覺風格與互動骨架，並將**已完成 `speak-human-tw` 與 `asd-ste100` 第二輪改寫**的定稿內容填入。範本是無產品規格的版型，所有 `{{...}}` 都必須替換。它取材自使用者的 NOR_Flash_DV_Guide_V6.html 閱讀架構，不包含該案例的實測資料。

每個功能使用一個 `article.chapter` 與唯一 id。新增章節時，導覽會由 JavaScript 讀取 `data-title` 建立。同步更新章內圖形、測項與錨點，避免重複 id。單功能時隱藏上一章／下一章按鈕。

## 內容與圖形

- 每章呈現概念、執行前說明、產品規則、共通方法、已選測項與流程、復原與判讀、待確認與來源。邊界／未定義用法只展開已選項目；沒有已選項目時簡述，移除範本 Flow X 及其導覽連結。範本不能反過來強迫增加測項。
- 首頁標明用途與機台範圍。每個已選測項的表前列情境依據、要抓的錯誤與不可取代性；多個測項共用 Flow 時仍逐項說明，可用短句或清單，不增加十幾欄。
- 補充候選獨立短表，僅列情境、新增價值與納入條件，不提供逐步流程或 Flow 連結。沒有候選時省略整表。合併／不採用的情境只摘要重要取捨。
- 需要 CP 建議時另列攔截目的、判定依據與證據狀態。無實測／失效案例支持者標「CP 候選／攔截假設待驗證」，不呈現為正式量產流程。不強制每個 DV 測項都對應 CP；沒有需求時移除 CP 區塊。
- 真實上下電只列機台允許時的補充建議；高頻與外部 RESET、/HOLD、/WP 操作不進入預設流程。不加入測試時間預算或成本欄位。
- 主測項表維持「步驟／做什麼／預期」；需要時增加觀察點，避免一張表塞十幾欄。
- 每個 Flow 的標題說明目的，必要時補「為什麼這樣測」。圖上只放階段與方向，細節留在測項表。
- 依功能產生 SVG 狀態／資料流、記憶體區域、資料前後差異或鎖定範圍圖。圖中文字清楚，箭頭對準節點；複雜流程分圖，不硬塞進固定尺寸。
- 產品行為圖須呈現初始狀態、指令與條件、結果或維持不變；含狀態行為的功能不得省略。無相關切換時改為資料前後對照並說明原因。未知分支標待確認。
- 在相關 Flow 的「為什麼這樣測」呈現重要異常路徑：初始狀態、操作順序、可能異常、違反規則、對應測項及誤判防範。標明推演／實測狀態，連結至測項。
- 每章明列假設、未涵蓋狀態／條件及影響，不只寫籠統的「未窮舉」。
- 參考依據附上方法來源 pstack /statechart（https://github.com/cursor/plugins/tree/main/pstack/skills/statechart），與本次產品規格來源分開。引用方法不代表執行其形式驗證工具。同時附上「文字編輯參考」列出本次實際讀取與套用的 `speak-human-tw` 與 `asd-ste100` 版本與日期。
- 範本總覽採 HTML 卡片與箭頭，SVG 可表達分支與狀態。兩者均不依賴 Mermaid。
- 正驗、反驗可放在同一個功能 Flow，不必強迫四類各自成章。
- 未定義項目列「可能結果／觀察點／要問 Designer」，不得拿範例樣品的行為當新料號預期。
- 沒有實測時標「待審查／未執行」，頁面不放虛構通過率或 PASS 統計。
- **文字與結構硬指標（`speak-human-tw` + `asd-ste100`）**：
  - 全文、圖說與表格內**嚴禁使用全形分號 `；`**（STE Rule 8.1），一律拆為句號短句或 `<ul><li>` 清單。
  - 超過 3 條規則或跨測項共通條件，使用 `<ul><li>` 清單呈現，禁止用 `<br>` 塞在同一長段落。
  - 同一測試目標頁或區域全篇固定同一代稱（如 `T`、`T2`），禁止在不同測項換用 `N`、`B` 等別名（STE Scan Checklist #1）。
  - 測項表的「做什麼」欄位採完整主動祈使句（含明確動詞），前置與禁止條件寫在動作之前。
  - 統一台灣工程用語（如 `address` 一律寫「位址」，禁止寫「地址」），刪除「此文件製作過程未操作晶片」等 AI 對 Prompt 交差的免責套話，且禁止在每個測項開頭重複蓋章「AI 推演，依 R…」。

## 技術要求

- 單檔 HTML，UTF-8、`lang="zh-Hant"`、viewport，CSS、JavaScript、SVG 內嵌。沒有外部字型、CDN、網路請求或建置步驟。
- 章節切換、上一章／下一章及測項連結可用，使用者能直接開檔閱讀。JavaScript 關閉時仍顯示所有章節。
- SVG 提供標題，按鈕可用鍵盤操作，有焦點樣式。不要只靠顏色傳遞結果。
- 窄螢幕讓圖表在各自容器捲動，不讓整個頁面橫向溢出。
- 列印顯示全部章節與參考依據，隱藏導覽、按鈕，使用白底黑字，避免表格被截斷。
- 文件文字與來源需作 HTML escaping，不用 `innerHTML` 注入不可信文件文字。

## 交付檢查

檢查已選測項的產品狀態、重要異常路徑、依據、不可取代性、假設與未涵蓋範圍。確認補充候選未展開流程，CP 證據未被誇大，設備限制一致。檢查來源、圖表／步驟編號、流程分支、前置／復原與實測狀態一致。確認產出的計畫沒有佔位符、錯誤跨章連結、範例產品資訊或程式實作宣稱。

檢查文字品質：確認產出的 HTML 內全形分號 `；` 數量為 0、無「地址／位址」混用、無目標頁別名輪替、步驟皆具動詞且條件在前、無 AI 交差式免責自白與機械重複的「AI 推演」印章。

實際開啟檢查桌面與窄螢幕、章節切換、直接錨點跳轉、列印全部章節，以及沒有 JavaScript 時內容仍可讀。不可把靜態結構檢查說成已做瀏覽器檢查。
