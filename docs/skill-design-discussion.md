## 第二、三輪已確認

4. 量產範圍先考慮指定功能的 CP，不擴成整顆產品的完整量產測試計畫。不考慮高頻測試。
5. 撤回時間預算與時數估算提案，不要求使用者提供測試時數。必要驗證不因成本而省略；精簡依必要性、重複性與新增判別價值決定。
6. AI 額外探索須說明尚未涵蓋的行為或失效假設；假設不冒充已證實機制。無新增判別價值就合併或停止。先前 Q6 提案中以高成本限制展開的條件，依 Q5 的明確決定不採用。
7. 機台限制：排除外部 RESET、HOLD、WP pin 硬體控制。Software Reset 優先；真實 Power Down／Power Up 可列機台允許時的補充建議，不納入預設必跑流程，也不以 Software Reset 結果替代。
8. 優先以新產品角度驗證功能與邏輯是否正確，再考慮 CP 測項攔截製程或 Sample corner case 造成的不良。兩者分開判斷。未定義用法正式納入 CP PASS／FAIL 前，須有確認的判定依據及攔截目的；Designer 確認的工程要求亦可作依據。
9. 每項簡述要抓什麼錯誤及其他測項為何不能取代。判斷目的相同的位址、pattern、指令排列合併為代表條件；確實造成不同判斷才分開。使用者指定的目的與條件仍保留。
